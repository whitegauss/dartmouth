## 4. トークンと質の関係（第一評価指標＝総トークン数）

- 4条件とも最終成果物は合格水準に達した。その前提で「質÷トークン」で見ると順序は明確：
- **C が圧倒的に効率最良**：総トークン 113,971（全体の9%）で、最も定量的な完了条件を持つ成果物を出した。出力比率32.7%も最高

- **D**：247,574（Cの2.17倍）。成果物は妥当だが後半の冗長な反復が消費を押し上げた。出力比率14.2%
- **B が最も非効率**：555,453（Cの4.87倍、全体の44%）を消費しながら、議論過程の切断が最多で、出力は最少（31,533、出力比率5.7%）。消費の94%が入力（13コール×長文脈の再送）で、「読む」側に消えている
- 同一議題（topic2）のA/B/C直接比較でも同じ結論：最少トークンのCが最も検証可能な結論を出し、最多トークンのBが過程の損失最大だった。「低エフォート×多人数」は本実験の範囲では、トークン効率でも過程の完全性でも高エフォート2名に劣る
- 条件Bの format_error 各10件の影響：最終集約は3セッションとも欠落なく生成されており、成果物の合否を左右はしなかった。影響したのは議論過程（他席案の全文が次ラウンドに渡らない）であり、今回の議題では結論の収束に致命傷にならなかったが、議題が難しくなれば集約自体が崩れるリスクとして残る

### format_error 10件の影響

- discussion は12発言（4席×3ラウンド）で、うち10件が `[FORMAT_FALLBACK]` で切断され、sessions.csv の format_error=10 と完全一致。切断した10件はいずれもちょうど818字で打ち切られており、上限到達による末尾切断であることが数値でも確認できる。完走したのは critic・quota の第1ラウンド発言のみ
- 失われたのは各発言の末尾（根拠の後半、設定例 YAML の後半、「未決」リストの途中など。例：manager 第1発言の未決が「人が解除す」で途切れる）。ただし全発言で「結論」と根拠の前半は残存した
- 相互参照への影響は topic2 の条件B（9fb235d5）より軽微だった。R2・R3 の各席は他席案を具体的に引用して評価・取り込みを行っている（manager R2 が quota の17kトークン試算と critic のエラー種別正規化を取り込み、quota R3 が critic の100KB上限を採用、等）。収束過程（R1：破棄 vs 保持の対立 → R2：初回保持・2回目破棄で合意 → R3：エラー種別分岐＋パッチ上限で精緻化）も追跡可能で、全席が役割内に留まった（topic2-B のような quota 席の役割逸脱なし）
- 結論：切断は過程の完全性を損なったが、今回の議題では結論の質と相互参照の実質は維持された。ただし末尾に「未決」や設定詳細を置く書式では集約が崩れるリスクが残る（§6 留保3 の次フェーズ課題を再確認）
