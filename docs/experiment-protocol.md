# Dartmouth 比較実験 T-001

実行順と品質判定を事前登録する。正本は [実行・記録表](experiment-sessions.csv)。本実験は議題1・2 × 条件A・B × 3反復の12セッション。条件Aは高エフォート2名、条件Bは低エフォート4名。議長は両条件で固定。ドライランは各条件1回。本実験の順序は Python の `random.Random(20261119).shuffle` で固定した。元の並び順は議題1・2、A・B、反復1・2・3の直積。CSV の最初の6列を実行開始後に変更しない。

## 勝ち条件

- 盲検化した最終議事録と事前の正解リストを照合する。議題1は必須論点5件、議題2は既知欠陥10件を採点し、各議題で3反復の平均合致数と最小・最大を出す。無作為抽出3件は別担当が照合し、評価者には条件を伏せる。
- 議題ごとの平均差が1件以上なら品質上位を採用する。上位条件のコスト比がドライラン後に確定する閾値を超えた場合、重要案件に限定する。閾値の仮値は1.5倍。
- 平均差が1件未満なら、総トークンと総呼び出し回数が少ない条件を採用する。両指標の優劣が分かれる場合は判定を保留し、双方を併記する。
- 正常終了で合致数0なら1正解あたりコストを N/A とし、0件発生数を記録する。失敗で採点できない場合は欠測とし、平均差による採否判定を保留する。書式異常を含むセッションを識別して別集計できるようにする。

## 記録方法

1セッション1行に全試行の合計を記入する。再実行は各セッション1回まで、ドライランを含む全体で最大16試行。失敗試行も呼び出し・トークン・時間・USDに含め、内訳は `log_ref` に紐付ける。取得できない数値は空欄とし、既知の0と区別して `notes` に理由を書く。トークンと所要秒数・呼び出し回数を記録し、参考USDは全セッションに同じ出典・換算方式を適用する。書式違反では再呼び出しせず、抽出をフォールバックした回数を `format_violations` に記録する。

## 開始前に固定する実行設定

- 対象ペルソナ4名の基準は git の blob ハッシュ（`git hash-object prompts/personas/<id>.md`）で固定する: manager `98ab59ba0819e6929b1bd00a8a8ea855f5f2833f`、engineer `ca594d32b37d2d626cd08f5556b16a864791888e`、critic `9c75963010ab812d9c5b5824fd2abedde95c17f6`、quota `7dbd76f8c6b321b218f04bb669b7089e38cea592`（当初の基準コミット 31bbce9 は 2026-11-20 の履歴書き換えで消えたため置き換え。中身は同一）。定義を変更した場合は実行対象のハッシュを記録する。リント規則は v1・暫定350トークン。
- 実験対象を検査するコマンドは、Dartmouth の Python 環境で `python scripts/lint_personas.py`。必須ブロック、暫定トークン上限、ファイルの欠落、テンプレート指定の欠落で終了コード1を返す。
- 出力パーサーは v1（`dartmouth.persona_output.VERSION`）。`dm stats` のペルソナ出力の書式違反件数を記録する。
- 具体的なモデルとエフォート、議題と正解リストの版、参考USD単価、ラウンド・タイムアウト・消費枠と費用閾値はドライラン後に記録する。
